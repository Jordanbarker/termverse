# Term Crunch (`@tt/term-crunch`)

A terminal-skills challenge game built **entirely on `@tt/core`** to prove the engine-reuse pattern. basePath `/termverse/term-crunch`. Run via `npm run dev:crunch` / `npm run build:crunch`.

> Monorepo-wide context (`@tt/core`, tech stack, deploy) lives in the repo-root `.claude/CLAUDE.md`. The shared engine skills `tmux` and `commands` are at root; this app's own skills are `challenges` and `apps/term-crunch:play-testing` (that one needs the scope prefix — termoil has a skill of the same name). Challenge copy rules and win-detection are owned by the challenges skill; the headless runner (`scripts/play.ts`), the `SOLUTIONS` playtest gate (`scripts/playtest_tracks.ts`, part of root `npm run check`), and Playwright driving are owned by the play-testing skill.

**It does NOT import termoil's story code** (no termoil `gameStore`/`COMPUTERS`, story flags, emails/piper/chip); anything shared comes through `@tt/core`, and `@tt/core/terminal/paneTypes` helpers stay pure and store-agnostic. The reverse holds too: `src/__tests__/coreSurface.test.ts` asserts the core registry has no story builtins **and** that core's `SUBCOMMAND_MAP` completion table offers no *sub*command core doesn't register (a denylist over sub-entries, so a termoil-only subcommand can't leak in through completions either). The player-editable `~/.zshrc` + `~/.tmux.conf` (Settings modal) are parsed only via the shared `@tt/core/terminal/{envParse,tmuxConfig}` parsers, never termoil's dotfiles or env-seeding code.

## Structure (`apps/term-crunch/src/`)

- **`challenges/`**: declarative challenge framework. `types.ts` (`Challenge`/`Step`/`ChallengeSnapshot`), `registry.ts` (ordered `CHALLENGES[]`, one file per challenge), `categories.ts` (tracks derived from challenge `type`: `all/tmux/git/fs/shell/vim`), `scheduler.ts` (pure SM-2-lite spaced repetition behind the completion-gate self-grades and `review`), `mastery.ts` (pure mastery-point/level module). See the `challenges` skill.
- **`state/gameStore.ts`**: lean Zustand store. Ports `@tt/core` window/pane actions, drives win-detection via `checkCompletion()`, tracks `bestTimes`/`reviewStats`/`mastery`/`lastAwards`, holds the player's `zshrc`/`tmuxConf`. Persist key `term-crunch-progress`.
- **`components/`**:
  - `GameShell.tsx` (layout); `TabManager.tsx`, a thin adapter over the shared `@tt/core/terminal/useTabManager` hook (store actions via `TabManagerAdapter`; the grade gate, per-pane `LineEditor`s, and editor/pager sessions via `TabManagerExtensions`; see the root `tmux` skill); `TabBar.tsx` wraps the shared `TmuxStatusBar`.
  - `ChallengePanel.tsx` (category/challenge dropdowns, frozen while `isGradeGateUp`, plus Restart, Settings, the `DueNotice`/`MasteryBlock` readouts and the grade gate); `SettingsModal.tsx` (`~/.zshrc` + `~/.tmux.conf` editors); `Toast.tsx` (transient notices; MP awards deliberately do **not** toast).
  - Target readouts `SchematicView.tsx`/`WindowStripView.tsx`/`FsTreeView.tsx`; cheat sheets `VimCheatSheet.tsx`/`TmuxCheatSheet.tsx` over `CheatSheet.tsx` (each file's header comment names what it must stay in sync with).
- **`engine/commands/navigation.ts`**: app-local navigation builtins (`challenges`/`goto`/`next`/`prev`/`track`/`review`), always available and listed by `help` as cyan meta commands. Handlers only queue a pending navigation; `runLine` applies it after committing shell state so `loadChallenge`'s fresh seed isn't clobbered.
- **`hooks/useTerminal.ts`**: wires xterm to the store; `runLine` delegates to the shared `@tt/core/commands/runPipeline` (no redirection or file-read events, those are termoil opt-ins); side-effect-imports `lib/availabilityPolicy` and feeds the allowlist to the shared suggestions engine. Incomplete input is held in a zsh-style secondary prompt by the shared `LineEditor` before reaching `runLine`.
- **`lib/`**: `machine.ts` (`CRUNCH_MACHINE`/`HOME_DIR`/`USERNAME`), `availabilityPolicy.ts` (registers the `AvailabilityPolicy` enforcing each challenge's `commands` allowlist), `seed.ts` (`buildBaseFs()` + `applyConfigs`), `defaultConfigs.ts` (`DEFAULT_ZSHRC`/`DEFAULT_TMUX_CONF`), `seedFs.ts` (shared seed writers/readers used by every challenge `setup`), `gitState.ts` (git-state reader for validators), `paneCompare.ts` (structural pane-tree compare, ignores ids), `windowLabel.ts` (bakes in the `crunch` host), `format.ts` (elapsed-time formatting).

## Window/pane UX

Mirrors the live game's tmux model (root `tmux` skill for the shared model, bindings, and conf parsing). Crunch-specific: every challenge starts attached to tmux session `"0"` (transient, never persisted; the detached-state rules for `checkCompletion` are in the challenges skill's win-detection section). The prefix key, status-bar theme, and pane focus/resize binds come from the player-editable `~/.tmux.conf` (Settings modal, default `DEFAULT_TMUX_CONF`), with built-in chords as fallbacks for unbound keys. The `~/.zshrc` (also Settings-editable, default `DEFAULT_ZSHRC`) is seeded into every challenge's fs and its aliases/exports activated for the session.
